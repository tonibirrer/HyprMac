# HyprMac

Tiling window manager for macOS, inspired by Hyprland. Swift/SwiftUI menu bar app. It is
unsandboxed and uses Accessibility plus private CGS/SkyLight APIs, so SIP can stay on. The Hypr
key is Caps Lock by default (remapped to F18 through `hidutil`); other keys can take the role
(`HyprMac/Models/HyprKey.swift`). BSP dwindle tiling, 10 workspaces with home monitors, a
scratchpad layer of floating windows, multi-monitor, focus-follows-mouse.

## Where work runs

- Repository work runs on the Mac mini hub (`zacharys-mac-mini`): edits, tests, builds, releases.
- The MacBook (`zachbook-pro`) is only the target for live-behavior tests of the signed Debug
  app. Build on the hub and copy the app over. Do not develop there.

## Rules

- `HyprMac.xcodeproj/project.pbxproj` is generated from `project.yml`. Run `xcodegen generate`
  after adding or removing files, then check `git status`. Contributors have shipped
  hand-edited, stale pbxproj files that dropped tests. On a PR, regenerate and compare.
- `TilingEngine` owns the BSP trees. Nothing else mutates a tree. `WorkspaceManager` owns the
  workspace-to-screen mapping.
- `Action` cases encode to frozen JSON wire keys, some legacy (`switchDesktop`,
  `moveToDesktop`, `moveWorkspaceToMonitor`). Never rename a wire key. Config decode is
  tolerant per keybind: one bad entry drops that keybind, not the config. Schema changes need
  a `ConfigMigration` step and `KeybindDecoderToleranceTests` updates.
- Ghost windows (closed while the app keeps running) keep their workspace assignment.
  User-facing emptiness (menu bar, Hypr+F next empty workspace) ignores the full hidden set.
  Admission and move capacity ignore only hidden minus reserved (minimized, hidden apps, and
  AX-unreadable windows are reserved). Suspect ghosts first on any occupancy bug.
- With Caps Lock as the Hypr key, macOS Modifier Keys settings must leave Caps Lock as
  "⇪ Caps Lock". "No Action" makes the key invisible to HyprMac. Never advise "No Action".
- Keep the red shake error feedback (`FocusBorder.flashError`) when a command cannot run.
- Coordinate math mixes NSScreen and CG origins. Read `docs/coordinate-systems.md` first.
- Never launch through the Xcode debugger. Accessibility is not granted there.

## How to verify

`xcodegen` and `gh` are in `/usr/local/bin` on the hub and `/opt/homebrew/bin` on Apple Silicon.
Add them to `PATH` if a non-login shell misses them.

Cheap checks (seconds):
```bash
git diff --check
plutil -lint HyprMac.xcodeproj/project.pbxproj
for s in scripts/*.sh; do bash -n "$s"; done
bash scripts/test-release-pipeline.sh    # prints "release pipeline invariants verified"
```

Test gate. It builds a testable library, never starts the window manager, and runs with an
isolated home, cache, and tmp under `build/sizing/isolated-tests/` (about 5 minutes):
```bash
./scripts/test-isolated.sh --debug-variant                  # full suite, no Sparkle
./scripts/test-isolated.sh --debug-variant BSPTreeTests     # one class
./scripts/test-isolated.sh --debug-variant BSPTreeTests/testName
./scripts/test-isolated.sh /path/to/Sparkle.xcframework     # release variant, as release.sh does
```
- The selection is a bare XCTest class name. A `HyprMacTests/` prefix runs 0 tests and still
  exits 0. Always check that `Executed N tests` shows a nonzero N and `0 failures`.
- A full run leaves a `config.json` fixture that breaks the next run. Before a second full run:
  `find build/sizing/isolated-tests/home -name config.json -delete`.
- `PollingSchedulerTests.testScheduleAfterPollFiresAgain` is a known wall-clock flake. If it is
  the only failure, rerun that test alone.
- Headless (no NSScreen), display-dependent tests throw `XCTSkip`. Engine tests still run by
  passing a synthetic `NSScreen` subclass through `DisplayManager(screenSource:)`. Use that
  pattern for new tests.
- After config schema or `Action` changes, also run `KeybindDecoderToleranceTests` and
  `ConfigMigrationTests` by name.

Release universal build, unsigned (resolves Sparkle over the network):
```bash
xcodebuild -project HyprMac.xcodeproj -scheme HyprMac -configuration Release \
  -derivedDataPath build/release-check ARCHS='arm64 x86_64' ONLY_ACTIVE_ARCH=NO \
  CODE_SIGNING_ALLOWED=NO build
lipo -archs build/release-check/Build/Products/Release/HyprMac.app/Contents/MacOS/HyprMac
```

Static analyzer:
```bash
xcodebuild -project HyprMac.xcodeproj -scheme HyprMac -configuration Debug \
  -derivedDataPath build/analyze CODE_SIGNING_ALLOWED=NO build analyze
```

Lint: `.swiftlint.yml` exists but `swiftlint` is not installed on the hub, and the last recorded
baseline already had errors. Do not claim a lint pass.

Tests do not prove window behavior. If behavior changed, deploy the Debug app to the MacBook
and exercise it there, or say plainly that it was not checked live.

## Debug app on the MacBook

`./scripts/build-debug.sh [Sparkle.xcframework]` builds the signed, universal
`HyprMac Debug.app` into `build/debug-canonical.noindex/Build/Products/Debug/`. Bundle id
`com.zachgray.HyprMac.debug`. Info.plist key `HyprMacSourceRevision` is
`<sha12>+<content hash>` of the source tree. It needs a cached Sparkle.xcframework, by default
at `build/audit-harness/Sparkle.xcframework`. `build/` is ignored, so copy it into a fresh
worktree. It also needs `rg` and the Developer ID identity.

The Debug app lives at `/Applications/HyprMac Debug.app` on the MacBook.
`docs/laptop-debug-deployment.md` is the dated record of the first install and still says
`~/Applications`. To redeploy a rebuilt app:
1. Build on the hub. Note the executable sha256 and `HyprMacSourceRevision`.
2. Tar only the one app, scp it over, extract into a staging directory, and run
   `codesign --verify --deep --strict` on it.
3. Find the exact running pid with `pgrep -f` on the full executable path (Debug or release).
   Send it `kill -TERM`, and wait until `ps -p` shows it gone.
4. Move the old bundle aside for rollback, move the new one into place, `/usr/bin/open` it.
5. Verify the pid's executable path, `HyprMacSourceRevision`, the executable sha256, and that
   the log shows `AXIsProcessTrusted=true` and `started`.

Accessibility trust survives because the signing identity and bundle id do not change.
Debug and release share `~/Library/Application Support/HyprMac/`. Back up those files before
any migration test.

## Logs

- The unified-log subsystem is the running bundle id: `com.zachgray.HyprMac.debug` for Debug,
  `com.zachgray.HyprMac` for release.
- Call `/usr/bin/log` by full path. A shell function can shadow `log`.
- Only `.notice` and above persist. `.debug` lines appear only in a live stream started before
  the repro: `/usr/bin/log stream --level debug --predicate 'subsystem == "com.zachgray.HyprMac.debug"'`.
- Debug builds also write every `hyprLog` call to `~/Library/Logs/HyprMac/<bundle id>.log`.
- Intermittent bugs: no repro, no guess fix. Add `.notice` logs at suspect paths, ship to the
  Debug app, and fix only once the logs confirm a cause. Keep those logs afterward.

## Release

Full guide: `docs/release.md`. `scripts/release.sh` bumps the version, runs the test gate,
builds, signs, notarizes, publishes the GitHub Release, updates the Sparkle appcast and the
Homebrew tap, commits, and pushes.

1. Update `WhatsNewFeatures.current` in `HyprMac/Welcome/WelcomeContent.swift` from
   `git log v<previous>..HEAD --oneline`. User-facing changes only. Each entry needs an SF
   Symbol, a short title, a one-line description, and a tint (`.cyan` default, `.magenta` for
   floating or scratchpad). Add `credit:` for outside contributors. Commit and push it first.
2. From a clean `main` checkout at exactly `origin/main`, on the hub:
   ```bash
   export DEVELOPMENT_TEAM=WYY8494SWG
   ./scripts/release.sh <version> [release-notes-file]
   ```
   Pick the version from `MARKETING_VERSION` in `project.yml`.

It needs the Developer ID identity and the `HyprMac` notarytool profile in the login keychain,
and an authenticated `gh`. The keychain must be unlocked. Set `KEYCHAIN_PASSWORD` or unlock it
first; the script never prompts. A locked keychain makes `codesign` fail with
`errSecInternalComponent`. Never rerun blindly after a failure; follow the recovery section of
`docs/release.md`.
